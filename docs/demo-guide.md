# 约两分钟演示指南

用途：展示真实单据、库存变化和错误拦截。以下时间为演练目标，未替用户计时；首次操作可慢一些，不为凑时长跳过确认步骤或把静态页面当成功结果。

## 演示前准备

1. 按 [README](../README.md) 安装环境，先检查网页可用；准备好浏览器窗口、商品文字和本指南。
2. 使用全新的独立模拟数据库，不在已有学习库重新登记期初，也不删除或清空学习库。只用下列虚构商品，不使用真实客户或企业数据。
3. 这套完整演示从创建商品开始，因此不预置商品、入库或出库数量。提前准备的是环境、空模拟库、浏览器和填写文本，业务数据在演示中真实产生。
4. 排练若超过两分钟，可减少讲解停顿、事先准备输入文字；若改成预先保存草稿的讲解版，必须明确告知哪些单据已准备，不能称全部现场创建。

### 启动独立演示库（仅供本人准备时执行）

下面命令在仓库根目录执行，使用与学习版不同的 5001 端口。它们写在指南中，交付整理时没有执行，也没有建立演示业务数据。

```powershell
New-Item -ItemType Directory -Force .local-demo | Out-Null
$demoDatabase = Join-Path (Resolve-Path .local-demo).Path 'demo-take-01.sqlite'
if (Test-Path -LiteralPath $demoDatabase) {
    throw 'This demo file exists. Choose a new take number; do not overwrite it.'
}
$env:DATABASE_NAME = $demoDatabase
$env:FLASK_DEBUG = '0'
& ./.venv/Scripts/python.exe -m flask --app inventory.app run --host 127.0.0.1 --port 5001
```

本公开副本使用按README在本目录建立的 `.venv`，不要套用原学习项目的环境路径。访问 http://127.0.0.1:5001 ，确保看到的是空模拟库。若不是空库，停止操作并检查文件路径。

`DATABASE_NAME` 是指定数据库路径的环境配置；端口是本机服务接收请求的入口。每次全新排练换一个未使用的文件名，例如 `demo-take-02.sqlite`，不要覆盖已有文件。只想恢复同一次演示时，保留原配置，仅重新运行最后一条启动命令，不要再执行“必须新文件”的检查块。

| 字段 | 模拟值 |
|---|---|
| 商品编码 | DEMO-001 |
| 商品名称 | 演示方格笔记本 |
| 单位 | 本 |
| 安全库存 | 15 |
| 期初/采购/销售数量 | 20 / 10 / 15 |
| 超售测试数量 | 16 |
| 日期 | 使用页面当天默认日期，保持本次演示一致 |

安全库存是提醒界限，不是商品数量。过账是正式确认并生成流水；保存草稿不等于过账。

## 约两分钟完整流程

| 时间目标 | 页面与操作 | 现场应看到的结果 | 可以说的话 |
|---|---|---|---|
| 0–15 秒 | 商品档案填写上表信息并新增 | 商品已建立，库存为 0 | “我基于开源项目，在人工智能辅助下改造了单仓的数量业务流程。” |
| 15–35 秒 | 业务单据选择期初入库 20，保存草稿；在详情核对后确认 | 单据已过账，生成 +20 流水，库存 20 | “期初表示开始使用系统时已经有的数量；草稿本身不增加库存。” |
| 35–55 秒 | 新建采购入库 10，保存并确认 | 新增 +10 流水，库存 30 | “这笔登记实际收到的采购商品。” |
| 55–75 秒 | 新建销售出库 15，保存并确认 | 新增 -15 流水，库存 15 | “确认时会检查当前库存，同一单据不能重复扣库。” |
| 75–90 秒 | 库存查询，找到模拟商品 | 余额 15、安全库存 15、低库存提醒 | “20 加 10 减 15 等于 15；小于或等于提醒界限就提示。” |
| 90–110 秒 | 新建销售 16，保存草稿，再尝试确认 | 提示库存不足；草稿保留，不增加流水 | “允许先保存草稿，但不能发出超过现有库存的数量。” |
| 110–120 秒 | 库存流水查看；必要时回库存页 | 只有 +20、+10、-15 三条流水，结存 15 | “失败的超售不进入流水，余额来自已过账记录，而不是手工填写。” |

最后应为 **4 张单据（3 张已过账、1 张失败后仍为草稿），3 条流水，库存 15**。若不一致，停止并记录，不为演示修改数据库或隐藏错误。原项目已有调拨历史，本项目新增的是对应期初、采购和销售单据的业务流水。

## 本人应能解释的三个问题

1. 为什么草稿不改变库存？——它仍待核对，只有正式确认才产生数量变化。
2. 为什么超售保存草稿成功，确认却失败？——草稿不占库存，确认要检查当时实际可用量。
3. 为什么必须有流水？——它说明余额的来源，并可追溯到对应单据。
